# ADR-0024: Lemma Identity Rule

## Durum
KABUL EDILDI

## Bağlam
Ayni yuzey form farkli anlamlar tasiyabilir:
- шэ = sut
- шэ = mermi

Bu homonimlerin nasil ele alinacagi belirsizdi.

## Karar
Model A: Homonimler TEK lemmaId altinda toplanir,
isHomonym: true ile isaretlenir.
Anlam ayrimi senses[] dizisinde yapılir.

## Ornek
LEMMA-SHE
├── sense: { lexemeId: 'L-SHE',  meaning: 'sut' }
└── sense: { lexemeId: 'L-SHE2', meaning: 'mermi' }

## Gerekce
- Lemma = surface form normalizasyonu
- Sense = anlam ayrimi (sense layer isi)
- Kod zaten bu modeli uyguluyor
- Embedding katmaninda sense ayrimi yapılabilir
- Lemma != Sense ayrimi korunur

## Zincir
Root -> Lemma -> Sense -> Concept

KISA DEVRE YAPıLAMAZ:
- Root -> Concept (YANLIS)

## Test Senaryolari
- шэ (sut) + шэ (mermi) -> LEMMA-SHE, 2 sense, isHomonym: true
- гу (kalp) -> LEMMA-GU, 1 sense, isHomonym: false

## Sonuçlar
- Lemma kimligi deterministik
- Sense ayrimi korunur
- Embedding/retrieval katmanlari stabil
